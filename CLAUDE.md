# SonicDNA — Claude Code project guide

SonicDNA is an autonomous sound-design lab built for the **Meta Global AI Developer Hackathon** (Indie track, solo build).
It takes a short reference sound, infers an editable synth/effects recipe, renders candidates, measures the difference,
and improves the recipe through logged experiments. "Sonic Alchemy" then transforms a recovered recipe toward a creative goal
while preserving a chosen property.

## Locked decisions (these override anything open in SPEC.md §15)

1. **One DSP engine: offline Python (NumPy/SciPy).** The browser only plays WAVs the backend returns. No Tone.js synth.
2. **Synthetic reference sounds only** for the MVP, generated by our own engine with known ground-truth params.
   Recorded guitar/environmental audio is a stretch goal.
3. **Division of labour between model and optimizer:**
   - Muse (Meta model) makes *structural* calls: oscillator type(s), which effect nodes are on, rough parameter regions.
   - The numeric optimizer (bounded coordinate search / Optuna / differential evolution) fine-tunes continuous params.
   - Headline comparison: **AI + optimizer vs optimizer-only vs random search**, same render budget (20 renders), 3 held-out targets.
4. **Model input:** send target descriptors as JSON **plus the spectrogram as a PNG** (vision). Do not depend on raw-audio input.
5. **Pitch is set from the f0 estimate (librosa pyin), never guessed by the model.**
6. **Alchemy v1 = brightness** (spectral-centroid target) with a preserve-pitch constraint.
   Demo prompt: "brighter and more atmospheric, keep the pitch." Only add a tremolo LFO node (rate, depth) if time allows —
   the original "metallic, preserve the rhythmic pulse" line is NOT supported by the current graph.
7. **Stack (changed Nov 4 at Albert's request):** Next.js frontend in `frontend/` with a thin FastAPI layer in `app/api.py`. Host: Render, one Docker service in public mode, with no Meta API key on the server.
8. **Export:** JSON recipe required; WAV optional.

## Architecture

```
reference WAV → validate/resample (44.1 kHz mono, loudness-normalised)
  → features (log-mag STFT, centroid, flatness, amplitude envelope, onset, f0)
  → planner (Muse: structural hypothesis, JSON-schema validated)
  → optimizer (continuous refinement within the chosen structure)
  → render (deterministic DSP) → compare (composite loss) → experiment log
  → best recipe → Alchemy variants → export
```

## Recipe schema v1.0

```json
{ "schema_version": "1.0", "sample_rate": 44100, "duration_s": 2.0,
  "oscillator": {"type": "saw", "frequency_hz": 220, "gain": 0.7},
  "envelope": {"attack_s": 0.02, "decay_s": 0.25, "sustain": 0.45, "release_s": 0.35},
  "filter": {"type": "lowpass", "cutoff_hz": 2800},
  "distortion": {"drive": 0.35},
  "delay": {"time_ms": 180, "feedback": 0.2, "wet": 0.15} }
```

Allowed: 1–2 oscillators (sine/saw/square), ADSR, low-pass filter, waveshaping distortion, simple delay. Every field has explicit bounds in `schema.py`.

## Planner contract

- **Inputs:** target descriptors, spectrogram PNG, allowed nodes + bounds, best recipe so far, recent experiments, remaining budget, user constraints.
- **Output:** `{hypothesis, action, proposed_recipe_or_delta, expected_effect, rationale}` via structured output.
- Reject out-of-range values or unknown nodes → retry once → deterministic fallback. Always keep best-so-far.

## Planner budget (Nov 4)

- Each Muse call takes about 28 s. One call proposes 3-5 candidate recipes. Cap: 4 planner calls per run.
- The model makes structural choices; the optimizer fine-tunes continuous parameters between calls.
- Every logged render records its source (model, optimizer or fallback) so provenance shows in the timeline.
- Go/no-go by 2:00 PM ET on Nov 4: AI + optimizer vs optimizer-only, same render budget, 3 held-out targets. If AI doesn't win 2 of 3, stop tuning, report it honestly, and move on.
- Feature-complete by 5:30 PM ET on Nov 4; bug fixes only after that.

## Non-negotiable rules

- Never cut deterministic rendering, evaluation, or provenance of model contributions.
- The experiment log must show **real** events. No prerecorded or fabricated AI reasoning. If a demo uses a cached run, label it as cached.
- The UI score is a **defined normalised metric**. Never call it "accuracy" or "% identical".
- Report results across held-out targets and against baselines, not one cherry-picked example.
- Use only self-generated or properly licensed audio.
- If audio or images are sent to an external model API, disclose it in the UI and the README.
